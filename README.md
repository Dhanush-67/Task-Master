# Task-Master

Task Master is a full-stack to-do list app with a React + TypeScript + Tailwind CSS frontend and a RESTful backend built with Node.js, Express, and PostgreSQL.

Vite handles hot reload and production builds.

## Tech Stack

- Frontend: React, TypeScript, Tailwind CSS, and Vite
- Backend: Node.js and Express
- Database: PostgreSQL

## Features

- Create, list, update, complete, and delete tasks through `/api/tasks`
- Server-side validation with structured JSON error responses
- PostgreSQL persistence with filtering by status and sorting by due date, title, or created date
- Clean backend separation between routes, controllers, services, and database setup
- React components in `frontend/`, with typed API requests and bundled Tailwind styles
- Postman collection for endpoint testing in [postman/task-master.postman_collection.json](/home/zeeton/repos/Task-Master/postman/task-master.postman_collection.json)

## Project Structure

- `frontend/main.tsx`: React entry point
- `frontend/App.tsx`: Task list, filters, loading state, and task actions
- `frontend/TaskCard.tsx`: Task display and edit, complete/reopen, and delete controls
- `frontend/TaskForm.tsx`: Create/edit dialog and validation feedback
- `frontend/api.ts`: Typed requests to the Express API and date normalization
- `frontend/types.ts`: Shared frontend task and filter types
- `frontend/styles.css`: Bundled Tailwind styles
- `index.html`: HTML shell for mounting React
- `vite.config.mjs`: Frontend build and development API proxy
- `dist`: Compiled frontend served by Express (generated by the build)
- `src/routes`: Express route definitions
- `src/controllers`: Request validation and response handling
- `src/services`: PostgreSQL queries and business logic
- `src/db`: Connection pool and schema initialization
- `src/middleware`: Not found and error handlers
- `db/schema.sql`: PostgreSQL table setup
- `tests/hosting.test.js`: Express frontend hosting and API checks
- `tests/e2e/tasks.spec.js`: Browser tests against the production build and development proxy

## Setup

Prerequisites: Node.js 20.19+ within the 20.x release line, or Node.js 22.12+; npm; and a running PostgreSQL database.


1. Install dependencies:

```bash
npm install
```

2. Create your environment file:

```bash
cp .env.example .env
```

3. Update `DATABASE_URL` in `.env` to point to your PostgreSQL database.

4. Build the React frontend:

```bash
npm run build
```

5. Start the server:

```bash
npm start
```

Express serves the built frontend and the API from the same origin. Rebuild the frontend after changing React code, or use the development server below.

The app will be available at [http://localhost:3000](http://localhost:3000), and the backend will auto-run `db/schema.sql` on startup.

## Frontend development

After installing dependencies and configuring PostgreSQL, start the backend in one terminal:

```bash
npm run dev
```

Start the React development server in a second terminal:

```bash
npm run dev:frontend
```

Open [http://localhost:5173](http://localhost:5173) for React hot reload.
Vite proxies `/api` requests to the Express port from `PORT` in `.env` (3000 by default).
For a backend on another host, set `API_PROXY_TARGET` to its URL.
The frontend uses the same relative `/api/tasks` URLs in development and production.

## Frontend and Backend Integration

React sends requests through `frontend/api.ts` to the existing `/api/tasks` endpoints. Task changes are saved in PostgreSQL, and the list reloads from the backend after a successful create, edit, complete/reopen, or delete operation. Filters and sorting are also applied by the backend.

- Development: Vite serves React and proxies `/api` to Express.
- Production: `npm run build` generates `dist/`, which Express serves alongside the API.
- Validation errors appear in the task dialog; list and task-action errors appear on the board.
- ISO due dates from the API are normalized to date-only values for display and editing.

```bash

npx playwright install chromium
npm run test:e2e
```

## API

### `GET /api/tasks`

Query params:

- `status=all|open|completed`
- `sortBy=dueDate|createdAt|title`
- `order=asc|desc`

### `POST /api/tasks`

```json
{
  "title": "Prepare project demo",
  "dueDate": "2026-04-25",
  "dueTime": "14:00"
}
```

### `PATCH /api/tasks/:id`

```json
{
  "title": "Prepare final demo",
  "dueTime": "16:30"
}
```

### `PATCH /api/tasks/:id/complete`

```json
{
  "completed": true
}
```

### `DELETE /api/tasks/:id`

Returns a success message when the task is removed.

## Error Response Shape

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Validation failed",
    "details": ["title must be at least 3 characters long"]
  }
}
```
